# Contributing to weDHack26

Welcome to **weDHack26**! 😎

weDHack26 is a collaborative hackathon built around technology, creativity, environmental problem-solving, wedding-week experimentation, and the general principle that interesting people can make interesting things together.

You do **not** need to be a professional programmer to participate.

## Challenge Tracks

Projects may be submitted to any of the official challenge tracks:

1. **Green Hack** — Environment
2. **Pattern Hack** — Annie's Pattern-Making Challenge
3. **Wedding Radio** — Production Challenge
4. **Wedding Hack** — Solve an actual wedding problem
5. **Hyper Hamster Wild Card** — Build something gloriously unnecessary

Projects may combine multiple tracks.

## Who Can Participate?

Anyone participating in weDHack26 may contribute.

Participation can be:

* In person
* Virtual
* Individual
* Team-based
* Technical
* Creative
* Experimental
* Ridiculously over-engineered

If you have an idea, you are welcome here.

## What Counts as a Project?

Almost anything that demonstrates useful, creative, or interesting work.

Examples include:

* Software
* Websites
* Data visualizations
* Hardware prototypes
* Physical inventions
* Games
* Art or interactive media
* Environmental tools
* Audio/radio production
* Pattern designs
* Accessibility solutions
* Wedding technology
* Automation
* Research or analysis
* Something nobody thought to ask for

A project does not need to be polished to be worth submitting.

## Getting Started

1. Choose a challenge track.
2. Form a team or work independently.
3. Create something.
4. Document what you made.
5. Submit your project before the announced deadline.
6. Be prepared to demonstrate or explain it during the final presentation.

## GitHub Workflow

For software projects, contributors are encouraged to:

1. Fork or clone the repository.
2. Create a branch for your work.
3. Make your changes.
4. Add documentation where appropriate.
5. Commit your work with a descriptive message.
6. Open a pull request when your work is ready.

For small projects or time-sensitive hackathon work, a simpler workflow is completely acceptable.

The goal is collaboration—not bureaucratic suffering.

## Code and Documentation

Please make reasonable efforts to make your work understandable to another person.

When possible, include:

* A README
* Setup instructions
* Dependencies
* Usage instructions
* Examples
* Screenshots or photographs
* Data sources
* Known limitations

If your project is experimental or incomplete, **say so**. Honest documentation is better than pretending a prototype is production-ready.

## External Materials

Do not commit material that you do not have permission to redistribute.

This includes:

* Copyrighted software
* Private information
* Passwords or credentials
* API keys
* Proprietary datasets
* Confidential documents
* Personal identifying information

If your project depends on external material, document where it came from and what permissions or licenses apply.

## Collaboration

Be kind.

Disagreement about an idea is fine. Disrespect toward a person is not.

We especially welcome contributions from people with different technical backgrounds and levels of experience.

Ask questions. Share unfinished ideas. Help somebody get unstuck.

## The Hyper Hamster Principle

weDHack26 is intentionally playful.

A technically impressive project is wonderful.

A beautifully designed project is wonderful.

A useful project is wonderful.

A completely unnecessary invention that somehow becomes the highlight of the entire event is also wonderful.

**Let's make something interesting, together!  More team than regime!**

## Questions

If you're unsure whether an idea fits, ask.

The answer is probably:

**"Lord willing yeah, let's see what happens."**
